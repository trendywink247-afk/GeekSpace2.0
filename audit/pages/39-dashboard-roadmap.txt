=== LOGIC ISSUES ===
- The roadmap items are hardcoded in the frontend. The "current phase" is Phase 102+ but
  the release notes only show phases 70-72 (Feb 2026). There's a gap — users see release
  notes that are months old. The roadmap content is stale and requires a code deployment
  to update.
- `window.confirm` is used for delete confirmation — not consistent with the rest of the
  app which uses inline confirmation UI.
- The suggestion voting uses vote value `1` (hardcoded in handleVote call). The handleVote
  function signature takes `(id: string)` only, with direction hardcoded to 1. There's no
  "downvote" handler visible in the preview — the UI shows ThumbsDown icon but it may just
  call vote with -1 from a separate handler (not visible in truncated read).
- `voteState` is initialized empty and populated from vote API responses. Initial vote
  counts are NOT pre-populated from the loaded suggestions data — so before a user votes,
  the displayed count comes from `mySuggestions` data. After voting, it shows from
  `voteState`. The display logic likely falls back correctly but there's a potential
  flash of stale counts.
- `loadError` is set as a string but only for partial failures ("Some data failed to load.")
  with no specific indication of which data failed. Success data still renders normally.
