=== LOGIC ISSUES ===
- Privacy toggles (showInDirectory, showAvatar, showLocation, showProjects, showActivity)
  have state but no save path — they are declared and rendered but no API call saves them.
  This is a silent placeholder that looks functional but has no effect.
- Profile form state is initialized from `user?.name || 'Alex Chen'` — if `user` is null
  on first render, the form shows hardcoded demo values. This is a graceful fallback but
  a new user would see "Alex Chen" as their default name.
- handleSave merges server response with existing user object (`{ ...user, ...updatedUser }`)
  but if the server strips fields from its response (intentionally or due to serialization),
  the merge could incorrectly preserve stale local values.
- Agent notification preferences and user-level notification preferences are saved to two
  different endpoints (PATCH /api/agent/config vs PATCH /api/me). A single "Save" action
  on the Notifications tab does NOT save both — only user-level notifs auto-save per toggle,
  and agent notifs are saved separately. The UI does not clearly communicate this split.
- The SettingsPage was read to line 399 out of ~700+ lines. The render JSX was not fully
  read; there may be additional issues in the remaining tabs' render code.
- `hasUnsavedChanges` is only tracked for the profile tab (explicitly set when profile
  fields change), but the beforeunload guard fires for ALL tabs if this flag is set from
  a previous profile edit even after saving. The flag may not clear properly.
