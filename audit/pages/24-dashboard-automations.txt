=== LOGIC ISSUES ===
1. Action configuration is incomplete in the UI: when creating a telegram-message automation, there is no field to enter the message text. The actionConfig object is built from only webhookUrl for webhook actions; other action types (telegram-message, create_reminder, log, manychat-broadcast) have no configurable payload in the form — their config will be empty `{}`, making them non-functional until edited via API.
2. The edit form does not restore webhookUrl from the existing automation's actionConfig (line 181: `webhookUrl: ''`), so editing an existing webhook automation loses the URL unless the user re-enters it.
3. `fmtNextRun` parses `trigger_config` from a raw JSON string using `JSON.parse(auto.trigger_config)` but the frontend Automation type likely already parses triggerConfig — this double-parse path uses `(auto as unknown as Record<string, unknown>).trigger_config` which may be undefined if the frontend object is already parsed, causing `fmtNextRun` to silently return null for valid time automations.
4. Run log pagination: clicking "Load More" appends entries to the list but there is no way to go back or reset to page 1 without a full page reload. The offset is additive only.
5. Stats card "Runs (7d)" is loaded separately from the main automations list and renders conditionally only when `automationStats !== null` — creates a layout shift (5th card appearing after initial render).
6. No confirmation dialog before deleting an automation — destructive action with no undo.
7. The toggle button disables the Run (Play) button when `!auto.enabled || isLoading` — but `isLoading` is a global dashboard loading state, meaning all run buttons are briefly disabled during any dashboard load operation.

Priority HIGH — Restore webhookUrl from existing automation's actionConfig when editing (currently lost on re-edit).
Priority HIGH — Fix fmtNextRun to use the already-parsed triggerConfig object from the frontend Automation type rather than re-parsing a raw string that may not exist.
Priority MED — Add a cron expression input (with human-readable preview) as an alternative to the integer interval field for time-based triggers.
Priority MED — Add delete confirmation dialog (or undo toast) for automation deletion.

Priority MED — Display the incoming webhook URL (e.g., /api/webhooks/:token) for webhook-trigger automations so users know what URL to point external services at.

=== SERVER ROUTES USED ===
GET    /api/automations                      — list (Redis cached 30s, ?enabled filter)
POST   /api/automations                      — create
PATCH  /api/automations/:id                  — update (name, description, trigger, action, enabled, triggerConfig)
DELETE /api/automations/:id                  — delete
POST   /api/automations/:id/trigger          — manual trigger (real engine)
POST   /api/automations/:id/test             — webhook test-fire (HTTP status, latency, body)
POST   /api/automations/:id/dry-run          — simulate without executing
POST   /api/automations/:id/duplicate        — create disabled copy
GET    /api/automations/stats                — summary counts + recent runs (7d)
GET    /api/automations/logs                 — all automation logs (paginated, status filter)
GET    /api/automations/:id/logs             — per-automation logs (paginated)
GET    /api/automations/dead-letters         — failed webhook delivery queue
POST   /api/automations/dead-letters/:id/retry — retry dead-letter webhook
