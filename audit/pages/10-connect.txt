=== LOGIC ISSUES ===
1. Brand inconsistency: Logo shows "GeekSpace" (line 73) while the rest of the app uses
   "Agentin Chat". This is a public-facing page (no login required) and the first thing
   external users see. Should show "Agentin Chat" to match brand identity and domain name.

2. Success CTA routes to /login not /signup: After accepting a connection invite, the button
   says "Sign up to GeekSpace" but links to /login. New users need /invite or /signup, not
   login. Existing users don't need prompting at all. The CTA is misrouted.

3. Single-use invite: accepting marks the invite as used (used_at timestamp set). If the user
   refreshes the success page or visits the URL again, they hit a 409 "Invite already used"
   error with no "you already connected" message. The error state is generic and confusing
   for a repeat visit.

4. No account linking for authenticated users: the page does not check if the acceptor is
   already logged in. An authenticated user who accepts an invite gets the same "Sign up to
   GeekSpace" prompt as a new user — there is no "You're already logged in, the connection
   is recorded" flow.

5. Owner notification via Telegram (server-side): sends Telegram message if agentCfg.notif_connections !== 0.
   The condition is checking for !== 0, meaning 0 disables and any other value (null, 1, etc.)
   enables. A NULL value from the DB would also enable. This is a logic edge case —
   should probably check === 1 (opt-in) rather than !== 0.

6. No rate limiting on the accept endpoint: a malicious actor could call
   POST /api/integrations/invite/:token/accept repeatedly (before the first accept commits)
   in a race condition, though the used_at guard prevents double-use. The info endpoint
   (GET) has no rate limiting either, allowing token enumeration probing.

7. axios is used while the rest of the app uses a shared api service (authService, etc.).
   This page uses a raw axios.get/post with a manually constructed API_URL. If the base URL
   config changes, this page may break independently.

=== SERVER ROUTES USED ===
GET  /api/integrations/invite/:token/info   — public, no auth, returns owner profile +
  expiry + email hint. Returns 404 (not found), 410 (expired), 409 (already used).
POST /api/integrations/invite/:token/accept — public, no auth, accepts { acceptorName?,
  acceptorEmail? }. Marks invite used, logs activity, optionally sends Telegram notification
  to invite owner. Returns { success: true, message: 'Connection established' }.
