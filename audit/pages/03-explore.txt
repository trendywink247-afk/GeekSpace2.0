=== LOGIC ISSUES ===
1. The Filter icon in the search bar right side is decorative — there is no advanced filter panel, no price filter, no availability filter, no sort option. The icon implies more functionality than exists. Users may tap it expecting a menu.
2. Tag filtering is server-side (correct) but the search input is also server-side with 300ms debounce. The debounce means there's a visible delay + loading flash on every keystroke after 300ms. On slow connections this creates a poor UX where the grid disappears and shows skeletons frequently.
3. The `eslint-disable-next-line react-hooks/exhaustive-deps` comment suppresses a warning about `profiles.length` being excluded from the useCallback dependency. This was done to avoid refetch loops but means the error fallback logic (checking `profiles.length === 0` inside catch) may not capture state correctly if profiles was previously loaded — the stale closure would see the old profiles.length.
4. The catch block in fetchProfiles: `if (profiles.length === 0) { setLoadError(...) }`. Since profiles is captured by closure and intentionally excluded from deps, if profiles had been previously loaded and the next fetch fails, `profiles.length` would be > 0 at time of catch, so setLoadError is never called. The user silently sees stale data with no error indicator.
5. No pagination or infinite scroll — the API likely returns a limited set of profiles and there's no way to load more.
6. Tag list is hardcoded in the frontend (`const allTags = [...]`) rather than fetched from the API. If new tags are added to user profiles on the server, they won't appear in the filter unless the frontend array is manually updated.
7. No sort options (by newest, most connections, alphabetical, etc.).
8. "Message Agent" button only shows for authenticated users. Unauthenticated visitors see only "View" on every card. There's no prompt to sign up when they try to message — the button is simply hidden. A CTA like "Sign up to message agents" could drive conversions.
9. The AgentToAgentChat component is used here but its authentication requirement is unclear from this file — if it requires auth, the button is already gated, so it should be fine.
