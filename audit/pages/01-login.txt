=== LOGIC ISSUES ===
1. OAuth buttons (GitHub, Google) are disabled in the UI with "OAuth coming soon" text, but the backend OAuth routes in oauth.ts ARE fully implemented (Google Strategy, GitHub Strategy, callback handlers). This is a frontend-backend mismatch — the feature is built on the server but not exposed in the UI.
2. No password strength indicator on signup. A user can sign up with "a" as a password (server has bcrypt with cost 12 but no minimum length validation — need to verify signupSchema). The server's signupSchema should enforce min length but client gives no feedback until rejection.
3. The redirect query param (?redirect=design, ?redirect=automations) passed from the landing page is never read by LoginPage after login. After successful login, the page always goes to /dashboard regardless. The redirect intent from the landing page is silently dropped.
4. Demo login pre-fill (alex@example.com / pass) exposes demo credentials visibly in the UI hint text "alex / pass" (sm:inline). This is intentional for a demo app, but worth noting that demo user alex/pass is publicly disclosed.
5. The form does not clear password on failed login attempt, which is standard browser behavior, but some implementations clear it for security.
6. isLoading state is shared from authStore — if another part of the app triggers a loading state, this button would incorrectly show as loading.
7. Username preview on signup shows "you.agentin.chat" when username is empty, then switches to the typed username. This is a nice UX touch but the domain shown (agentin.chat) may differ from actual deployment domain (ai.geekspace.space vs ai.agentin.chat).
