=== LOGIC ISSUES ===
1. Mixed save strategies: Personality switch and Model Preference save immediately (auto-save), but Style, Voice, Tone, Sliders, Name, and System Prompt require the Save button. There's no visual indication of which fields are auto-save vs. require the button. The Save button label doesn't indicate what fields it covers. A user could change the personality (saved instantly) then the system prompt (not saved) and think everything was saved.

2. On "Save Changes" click, handleSave calls updateAgent() which does an optimistic update then API call. If the API fails, the catch block does nothing — local state is NOT reverted and the store is updated optimistically. The user would see no error feedback, and the data might not match what's on the server.

3. The memory summary link uses a hard <a href="/dashboard/memory"> anchor instead of React Router's navigate(). This causes a full page reload on click instead of client-side navigation. All other navigation in the dashboard uses the router.

4. The sync useEffect has a large dependency array (agent.id, agent.mode, agent.voice, agent.creativity, agent.formality, agent.systemPrompt, agent.name, agent.personality, agent.model_preference, agent.displayName, agent.greeting). If the store updates any of these fields from elsewhere (e.g., a background refresh), it will overwrite any unsaved local changes the user has made. This is a form clobbering issue.

5. The System Instructions section uses the Image icon (from lucide) as its section icon — clearly a wrong icon (should be Terminal, Brain, or Code). This is a copy-paste error.

6. The Save button is positioned fixed at the bottom-right but scrolls with the page (it's not sticky). On long pages (personality section + all other sections), the Save button may be far below the fold when the user finishes editing the first section.

7. handleSave sends displayName: displayName || undefined and greeting: greeting || undefined. This means clearing the display name (setting it to empty string) sends undefined to the server, which leaves the old value unchanged instead of clearing it. The user cannot delete their display name.

8. The personalities data comes from GET /agent/personalities (unauthenticated endpoint, Redis-cached 1h). This means all users see the same personalities, which is correct. However, if the personalities config changes on the server, the cached data won't update for up to 1 hour.

=== IMPROVEMENTS ===

[HIGH] Add visual distinction between auto-save fields (personality, model preference) and save-on-button fields (all others). Consider labeling them or adding "Saved" indicators per-section.

[HIGH] Handle save errors gracefully — show an error toast or alert when updateAgent() fails. Currently fails silently.

[HIGH] Fix form clobbering — use a ref to track "has user made changes" and skip the sync useEffect when the form is dirty. Alternatively, only sync from store on initial load (agent.id truthy for the first time).

[MED] Add "sticky" Save button at page bottom (position:sticky bottom-0) so it's always accessible without scrolling to end of page.

[MED] Replace the Image icon in "System Instructions" section header with a more appropriate icon (Terminal, Code, or Cpu).

[MED] Allow clearing displayName and greeting — send empty string to server when field is explicitly cleared (use null or empty string, not undefined).

=== SERVER ROUTES USED ===
GET   /api/agent/config        — load agent config (via dashboardStore.loadDashboard on mount)
GET   /api/agent/personalities — load personality definitions (Weebo/Edith/Jarvis + metadata)
GET   /api/agent/memory        — load top 5 memory entries for summary card
PATCH /api/agent/config        — save agent config (via updateAgent in dashboardStore):
    - Personality switch: { personality: id }
    - Model preference: { model_preference: value }
    - Save button: { name, displayName, greeting, mode, voice, creativity, formality, systemPrompt }
