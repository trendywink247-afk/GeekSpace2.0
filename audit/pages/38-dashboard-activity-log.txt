=== LOGIC ISSUES ===
- CLIENT-SIDE category filter over server-paginated data: The server returns 25 items per
  page. Applying a category filter client-side only filters those 25 items. If the user
  loads the first 25 activities and selects "Agent" filter, they only see Agent entries
  within those 25 — not all Agent entries in the DB. This is misleading: count badge
  shows correct count from current page, not total per category in DB.
- Pull-to-refresh bug: `handlePullRefresh` fires but does not update state:
  `const res = await userService.getActivity(50)` — result is not used.
  The wrapper likely provides haptic/visual refresh but no data update happens.
- Individual delete button is hover-only (group-hover) — entirely inaccessible on mobile.
  There is no mobile-friendly alternative (no swipe, no long-press, no visible button).
- The `counts` object (badge numbers per chip) reflects client-loaded entries only, not
  total DB counts per category. Combined with pagination, these counts are misleading when
  total > 25 items.
- `userService.getActivity` and `activityService.export` are two different services for
  the same data source — slight API surface inconsistency.
- Date inputs use native HTML date picker — appearance varies by browser/OS.
  No date range validation (to < from is allowed without warning).
