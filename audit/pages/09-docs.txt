=== LOGIC ISSUES ===
1. Articles are non-interactive: article cards have hover styles (hover:border-[#00F0FF]/30)
   suggesting they should be clickable, but they render as plain divs with no href, no onClick,
   and no navigation. This creates a deceptive affordance — users will try to click them.

2. Search does not include article summaries: filtering uses
   d.articles.some((a) => a.title.toLowerCase().includes(...)) but does not check a.summary.
   A user searching "encryption" would find the "API Keys & Security" section (title match)
   but searching "tokens" or "OAuth" would miss articles where only the summary contains the term.

3. All content is hardcoded placeholder data: no API call is made. Article summaries are
   1-sentence stubs. This page delivers no real documentation value to users.

4. Rate limit value hardcoded in content: "200 requests per 15-minute window per user" in the
   Terminal & API section may not match the actual configured server rate limits. No single
   source of truth.

5. Contact email is plain text, not a mailto: link. Same issue as StatusPage.

6. Only one accordion section can be open at a time (setExpandedSection toggles). For a docs
   page, users may want multiple sections open to compare content.

7. No anchoring / deep-linking: no way to link to a specific section or article (no hash routing,
   no section IDs in the URL).
