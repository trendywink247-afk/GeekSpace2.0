=== LOGIC ISSUES ===
1. ONLY ONE TOOL: The TABS constant defines only one tab (`json`). The component comment says "developer utilities for working with AI" (plural) but there is nothing else. The file name "AISpecialistPage" and icon (Cpu) suggest more tools were planned. The tab container design allows for easy addition of more tools, but none are implemented.

2. SYNTAX HIGHLIGHTER XSS NOTE: The output panel uses `dangerouslySetInnerHTML={{ __html: highlight(output) }}`. The `highlight()` function HTML-escapes `&`, `<`, `>` before applying regex spans, so raw user JSON is properly sanitized before injection. This is safe as implemented.

3. ERROR LINE NUMBER BROWSER COMPATIBILITY: The `getErrorLine` function relies on SyntaxError messages containing "position N" (V8 format). Firefox uses "JSON.parse: unexpected character at line X column Y" — different format. Safari uses "JSON Parse error: Unrecognized token". In Firefox/Safari, `match` will return null and line number will be undefined — the error box will still show the message but not the line number. Not critical but degrades DX on non-Chrome browsers.

4. NO TOOL HISTORY: There is no way to recall previously formatted JSON snippets. Each session starts fresh (component state only, no localStorage persistence).

5. NO VALIDATION-ONLY MODE: The auto-validation on change is effective, but there's no explicit "Validate" button that only checks without formatting. Users who want to just check validity must click Format and observe the result, which also changes the output.

6. LARGE JSON PERFORMANCE: The syntax highlighter runs on every format/minify call using regex replacement. For very large JSON (1MB+), this may cause UI freezes since it's synchronous. No debouncing or chunking.

7. TOKEN ESTIMATE ACCURACY: chars/4 is a rough GPT-style estimate. For non-English characters or specialized models (Kimi K2, Claude), tokenization differs. No model-specific selector for token estimation.
