=== LOGIC ISSUES ===
- No polling: unread count badge only updates on manual refresh. If Telegram messages
  arrive while the user is on the page, they won't see the count update without refreshing.
- Archive removes item from UI but filter state stays on current filter — correct behavior
  but if user is on 'unread' filter and marks a message read, it stays visible until refresh.
  Actually re-reading code: mark read only updates read:1 in local state, does NOT remove
  from 'unread' filtered view automatically. User must switch filters to see effect.
- The unread badge in the header is derived from local messages array. If user switches to
  'unread' filter, all visible messages are unread (correct), but the badge still reflects
  all messages count, not just visible ones.
- Reply error clears itself only if another error occurs. No way to dismiss error banner
  except triggering another action.
- No confirmation on delete (permanent hard delete, no undo).
- incoming_reply route: POST /api/inbox/:id/reply — the inbox.ts route file was only read
  partially; need to verify this route actually exists (InboxPage assumes it does).
