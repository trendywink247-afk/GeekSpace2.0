=== LOGIC ISSUES ===
1. The contact modal fetches a nonce before submission. If Redis is down, the nonce fetch is non-fatal (try/catch swallows error and proceeds with nonce=undefined). But the server then validates the nonce only if provided: "if (nonce) { ... validate }" — meaning Redis failure gracefully degrades to allowing submission without nonce validation. This is intentional and documented.

2. The chat panel is duplicated in JSX — desktop panel (hidden lg:flex) and mobile overlay (lg:hidden) are two separate implementations with the same logic but different styling. This means any bug fix or feature addition to the chat must be applied in two places. High maintenance burden.

3. Agent status polling starts only when chatOpen=true (within the same useEffect that runs on username/agentEnabled/chatOpen changes). But the poll interval is set up inside the effect after an early return `if (!chatOpen) return`. This means the interval is never started unless chatOpen changes while the effect re-runs. However, since chatOpen is a dependency, the effect re-runs when chat opens, which sets up the interval. This works correctly but the dependency interplay is subtle.

4. The `personalityMeta` only handles 'edith', 'jarvis', 'weebo'. If a portfolio has a personality value outside these three (e.g., 'default', 'custom'), the fallback is `|| personalityMeta.jarvis`. This is safe.

5. Social links construct URLs as `https://${portfolio.social.github}` — if the stored value already contains "https://", this would create "https://https://...". No sanitization of the protocol is done. Should check if value already has a protocol.

6. OG tags are added via document.createElement dynamically on mount and cleaned up on unmount. This only works for SPA navigation. When the page is server-rendered or crawled, the server-side route in portfolio.ts handles OG meta via HTML response — this is the correct pattern.

7. The contact modal does not reset `contactName`, `contactEmail`, `contactMessage` when it's closed without sending. If a user partially fills the form, closes it, and re-opens it, they'll see their previous draft — this could be desirable (draft persistence) or confusing depending on UX intent.

8. Error on portfolioService.getPublic: `.catch(() => {})` silently swallows all errors. If the API returns a 403 (private portfolio), 500, or network error, the user sees nothing — no error message. The component just shows nothing (isLoading=false, portfolio=null → "Portfolio not found"). This conflates private/nonexistent/error states.

9. The desktop chat panel close button clears chatOpen state but does NOT reset chatHistory. Re-opening the panel will show the previous conversation — this may be intentional for continuity.

=== IMPROVEMENTS ===
HIGH — Fix social link URL construction: Check if stored value already starts with 'http://' or 'https://' before prepending 'https://'. Otherwise double-protocol URLs will be broken links.
HIGH — Fix silent error swallowing on portfolio fetch: Distinguish between 404 (not found), 403 (private), and network errors. Show appropriate messages ("This portfolio is private", "Failed to load — try again").
HIGH — Deduplicate chat panel code: Extract a shared ChatPanel component used by both the desktop side panel and mobile overlay. Currently the same JSX block is written twice (~150 lines each).
MED — Contact modal: Reset form fields when modal is closed (setContactName(''), setContactEmail(''), setContactMessage('')) to avoid stale draft leaking into next open.
MED — Add "private portfolio" handling: If the portfolio is marked is_public=false, the server returns 404 JSON. The frontend should show a clearer message ("This portfolio is set to private") rather than generic "Portfolio not found".
MED — Personality fallback display: Show a neutral emoji/icon for unrecognized personality values rather than silently defaulting to Jarvis behavior with Jarvis questions.
LOW — Chat history is not persisted across page navigations. If a user navigates away and returns, the conversation resets. Consider storing in sessionStorage for better UX continuity.
LOW — View count and connection count are shown as raw numbers without formatting. Very large numbers (e.g. 1000000) should use toLocaleString() — the viewCount already uses this, but connectionCount does not.
LOW — Add "powered by" link in footer to use a proper anchor tag rather than just a text span.
