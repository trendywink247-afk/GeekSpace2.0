=== LOGIC ISSUES ===
- `gs usage today` divides monthly totals by 30 to estimate daily usage. This is
  mathematically wrong and misleading (actual today's usage requires a different API call).
  Shows as "usage today" but is actually "average daily usage this month".
- `gs deploy` outputs fake success text with a time-based deploy ID. Users could
  mistake this for a real deployment trigger. There is no actual deploy happening.
- `gs schedule tomorrow` is hardcoded — always shows "No items scheduled yet" regardless
  of actual tomorrow's reminders. Should query the reminders store filtered by date.
- Commands are matched with `trimmedCmd = cmd.trim().toLowerCase()` — case-insensitive
  matching is fine, but the user's original case is shown in the input echo, creating
  a visual mismatch (you type "GS ME", it shows "GS ME" in prompt but matches "gs me").
- `getResponses()` is called inside the event handler every keystroke. It captures
  store values via closure correctly since it calls `useDashboardStore.getState()` for
  integrations/automations, but other values (user, reminders, usage) are captured as
  React state — these will be stale if the store updates while the terminal is open.
  This means `gs credits` could show old credit balance if billing updated in background.
- `addCommand` from terminalStore is called twice for AI commands (once with "Thinking..."
  placeholder, once with actual response) — both entries get stored. The "Thinking..."
  entry persists in history with the input, and the response is a separate entry.
  This creates double entries for AI commands in the history.
- Copy button is hover-only — inaccessible on mobile.
- No max history length — history array grows unboundedly in the store.
