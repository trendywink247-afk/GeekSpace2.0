=== LOGIC ISSUES ===
1. Dead code: `handleVoiceInput` has two consecutive `return` statements at lines 192-194 (the second `return` after the not-supported message is unreachable but causes a TypeScript/lint warning).
2. `isOverdue` helper function at line 661 does a lookup using `r.datetime === datetime` across all reminders array which is O(n) and potentially incorrect if two reminders share the same datetime string; should look up by id instead.
3. Filter persistence saves to localStorage immediately on every filter change but does not clear stale values if a user is logged out and another user logs in — filters leak across accounts.
4. `handleNaturalAdd` always hard-codes `channel: 'telegram'` and `category: 'personal'` regardless of the legacy form defaults or user preferences — no way to customize channel from the NLP flow.
5. Calendar view toggle exists in UI but the actual calendar rendering is not visible in the audited portion (lines 1050+); if it's a stub or basic month grid, it may not match the rich feature set of the list view.
6. Overdue banner shows "Mark all complete" only when overdueReminders.length > 3 (more than 3, not 3+). This is inconsistent with the comment "4+ overdue items" — edge case: exactly 3 overdue items get no banner.
7. Bulk-snooze for active reminders uses `selectedActiveIds` state but bulk operations for completed use `selectedIds` — two separate selection states that cannot be operated on simultaneously (reasonable but potentially confusing UX).
8. No confirmation dialog before bulk-delete of active reminders — destructive action with no undo.
9. `parsedReminder.datetime.toISOString()` in `handleNaturalAdd` will use UTC; if the natural language parser produces local time, the stored datetime may be off by the user's UTC offset.
