=== LOGIC ISSUES ===
- Initial useEffect has empty deps array `[]` (eslint-disable comment) but captures
  `summaryRange` and `chartRange` initial values. If component remounts with different
  defaults (unlikely now, but fragile) it would not pick up the right initial ranges.
- Error shown ONLY if all 6 endpoints fail (`failures === 6`). If 1-5 fail, partial data
  is displayed silently with no user notification. A user could see cost = $0.00 with no
  indication that the data fetch partially failed.
- `handlePullRefresh` does not update `eventsPage` counter back to 1 when refreshing —
  if user is on page 3 and pulls to refresh, new data is fetched for page 3 (not page 1).
- `usageService.latency()` is called to populate hourly data but the parameter name
  'latency' is semantically misleading — it actually returns hourly request counts.
  Naming inconsistency between service method name and data purpose.
- The Billing summary card in this page is a simplified view (plan/credits/allowance/usage).
  The full BillingPage has more detail. These two pages could show divergent data if
  billing cache differs.
- Charts only render client-side due to `mounted` guard. This means there's a brief
  flash of skeleton → content on first load.
