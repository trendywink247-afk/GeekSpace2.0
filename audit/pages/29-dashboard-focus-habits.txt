=== LOGIC ISSUES ===
1. "View now" for deferred messages calls `setDeferredCount(0)` and `void load()` — this clears the visual indicator but doesn't actually navigate the user to see the held messages. The deferred messages remain in the DB buffer and the user has no way to read them from the UI; they are presumably delivered when focus mode ends.
2. `useTimer` uses `Date.now()` on every tick to compute elapsed time from `session.started_at`. If the user's device clock drifts or the browser tab is backgrounded/throttled, the elapsed/remaining calculation may become slightly inaccurate. The session started_at timestamp is an absolute Unix ms, so accuracy should be fine in practice, but the 1-second interval may drift on throttled background tabs (requestAnimationFrame-based approach would be more reliable).
3. The timer countdown shows remaining time only if the session has a `duration_min` set. If a user starts a session without a duration (open-ended), the timer shows elapsed time with "elapsed" label — this is correct behavior but not obvious from the UI since the duration selector always defaults to 25 min in the modal.
4. `handleEndFocus` posts `{completed: true}` unconditionally — there is no way to end a session as "abandoned/incomplete" from the UI. This inflates the completion stats.
5. All API calls in `handleStartFocus`, `handleEndFocus`, `handleLogHabit`, `handleAddHabit`, `handleDeleteHabit`, `toggleFocusMode` silently swallow errors in empty `catch {}` blocks — the user gets no feedback on failure.
6. The Add Habit modal has no `description` or `frequency` fields despite the server accepting them — these are silently ignored, leaving all habits with null description and null frequency.
7. Delete habit button uses inline "x" text instead of an icon (e.g., Trash2) — inconsistent with the rest of the design system and visually less clear.
8. The page `load()` function is called on mount (via useEffect) and after every action — it fires 4 parallel API calls (active session, habits, notification settings, deferred count). If the server is slow, this can create 4 concurrent loading states with no unified loading indicator.
9. No confirmation before deleting a habit — streak data and log history are lost immediately.

=== SERVER ROUTES USED ===
GET    /api/focus/active           — get active focus session for user
POST   /api/focus/start            — start new focus session {goal, durationMin}
POST   /api/focus/end              — end active session {completed}
GET    /api/focus/history          — session history (NOT used in UI — endpoint exists but page doesn't call it)
GET    /api/focus/summary          — aggregate stats (NOT used in UI — endpoint exists but page doesn't call it)
GET    /api/focus/deferred         — count of messages held during focus mode
GET    /api/focus/settings         — notification settings (focus_mode_active, dnd_start, dnd_end, etc.)
PATCH  /api/focus/settings         — update notification settings

GET    /api/habits                 — list habits with streak + logged_today
POST   /api/habits                 — create habit {name, icon, description, frequency, targetTime}
DELETE /api/habits/:id             — delete habit
POST   /api/habits/:id/log         — log habit as done today {note?}

Note: GET /api/habits/:id/stats (habit stats endpoint) exists in the router but is not called by the UI. The habitsRouter is mounted separately from focusRouter in server/src/routes/focus.ts.
