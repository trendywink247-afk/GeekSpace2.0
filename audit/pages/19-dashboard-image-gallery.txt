=== LOGIC ISSUES ===
1. TWO SEPARATE IMAGE SYSTEMS: The Image Gallery page (`/dashboard/gallery`) uses `imageAsyncService.gallery()` which calls GET `/api/image/gallery` (the older async/job-queue based route in `server/src/routes/image.ts`, Phase 81). The Image Generator page (`/dashboard/image-gen`) uses `imageService.list()` which calls GET `/api/images` (the newer sync route in `server/src/routes/images.ts`). These are DIFFERENT routes, different tables (user_images vs images from image.ts gallery), and potentially different data. A user generating images on /image-gen will NOT see those images on /gallery, and vice versa. This is a significant data consistency issue.

2. NO LIGHTBOX/ZOOM: Unlike the Image Generator page which has a proper lightbox modal, the Gallery page has no click-to-expand. Users can only view the tiny thumbnail or download the image. The hover overlay is desktop-only and invisible on mobile.

3. NO DELETE: Users cannot delete images from the Gallery page. They must navigate to /image-gen to delete. Since both pages use different endpoints, a user managing "gallery" images may not even find them in the Image Generator gallery.

4. DOWNLOAD CROSS-ORIGIN ISSUE: The `download` attribute on an anchor tag only forces a download for same-origin URLs. If image_url is a Pollinations CDN URL or an external HuggingFace URL, the browser will open it in a new tab instead of downloading. Only images served from /api/images/cache/* (same-origin cached HuggingFace images) will download correctly.

5. "LAST 30" HARDCODED LIMIT: There is no pagination or indication of how many images exist beyond 30. If a user has 35 images, the oldest 5 are silently omitted. No count or "showing X of Y" label is shown.

6. EMPTY STATE MISLEADING: The empty state tells users to type `/image [prompt]` in chat to generate. But images generated via /dashboard/image-gen use a different endpoint. If a user generates images via the Image Gen page and then visits the Gallery, they may see an empty state even though they have images — because the gallery reads from a different data source.

7. NO ERROR RETRY: On error, there is only a persistent error box. No automatic retry, and the Refresh button is disabled while loading but there is no way to dismiss the error and try again other than clicking Refresh manually.

=== SERVER ROUTES USED ===
GET /api/image/gallery   — fetches last 30 images (imageAsyncService.gallery() via imageAsyncRouter in image.ts)

NOTE: This is a DIFFERENT route than what Image Generator uses:
  - Image Generator uses: GET /api/images  (imagesRouter in images.ts, reads user_images table)
  - Image Gallery uses:   GET /api/image/gallery  (imageAsyncRouter in image.ts, reads different images table)

These two tables/routes are not synchronized. Images appear in one but not the other.
