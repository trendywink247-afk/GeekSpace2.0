=== LOGIC ISSUES ===
- The `cfgPersonality` state defaults to 'weebo' but the createAgent form uses a separate
  `newAgentPersonality` state. These are independent — changing the Config tab personality
  doesn't affect the create form, which is correct but could confuse users.
- `configDirty` is set to false after agent selection loads config. If the user makes
  changes, saves, then re-selects the same agent, the config reloads from the agents array
  (which was fetched on initial load and may be stale). A fresh fetch after save would be
  more accurate.
- Tool assignment uses a string[] parsed from `agent.assigned_tools` JSON field.
  If the JSON is malformed, it silently falls back to empty array. No visual indication
  of parse failure.
- Recent activity polling (every 30s) calls `picoService.getTasks({ limit: 10 })` but the
  main tasks list was loaded with limit 50. The polling updates `recentTasks` (separate
  state) rather than `tasks`. This means the Tasks tab doesn't auto-refresh — only the
  bottom "recent activity" strip updates.
- Cron job `cronConfig` is a raw JSON textarea. No validation of JSON syntax before submit
  (server likely validates but user sees no inline error on malformed JSON).
- Agent slots are plan-limited (free=1, others=2-3) but the enforcement is server-side.
  The UI shows empty slots up to the limit but if the server returns fewer agents than
  plan allows, the UI may show incorrect empty slots.
