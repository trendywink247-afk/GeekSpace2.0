=== LOGIC ISSUES ===
- Two parallel billing systems exist on one page: credit-based plans (intro/monthly/halfyear/yearly)
  AND Stripe subscription plans (basic/pro). The relationship between them is unclear to users.
  A user could be on both systems simultaneously, which may create confusion about what
  they're actually paying for and what features each system unlocks.
- The `handleUpgrade` function for credit-based plans silently calls `billingService.upgrade()`
  with no payment collection — appears to be a free upgrade mechanism for internal plans.
  This works only if these plans don't require payment (possibly credit-based internal system).
- Stripe plans show INR prices in the UI header ("Rs 99/mo") but the toggle between USD/INR
  affects the credit-based plan prices, not the Stripe prices. Stripe prices are hardcoded
  in the component (₹99/$1.19 and ₹299/$3.59). Inconsistency.
- `events` state uses type `UsageEvent[]` but is loaded from `billingService.getEvents()`
  which returns up to 20 items (no pagination shown). UsageAnalyticsPage shows full
  paginated events — BillingPage shows a truncated subset.
- `currency` defaults to USD but is set to INR if `sub.currency === 'INR'` — this works
  but the toggle state could diverge from server if user changes currency in another session.
- `upgrading` state is per-plan-id but `checkingOut` is per plan-type string ('basic'/'pro').
  Both spinners display during their respective operations — consistent but uses two separate
  loading mechanisms for logically similar operations.
- Plan comparison table uses `PLAN_DISPLAY` data which is hardcoded in the component.
  If server adds new plans, the comparison table won't reflect them without code changes.

=== SERVER ROUTES USED ===

GET    /api/billing/usage          — 30-day daily usage history
GET    /api/billing/events         — last 20 credit usage events
GET    /api/billing/stripe-status  — Stripe subscription status
POST   /api/billing/upgrade        — upgrade to credit-based plan
POST   /api/billing/daypass        — activate $1 day pass
POST   /api/billing/checkout       — create Stripe checkout session
