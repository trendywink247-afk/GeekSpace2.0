=== LOGIC ISSUES ===
1. No auto-refresh: the page only checks once on mount. A status page typically polls every
   30-60 seconds so users don't need to manually refresh. If a service recovers, the page
   stays red until manual refresh.

2. Typo in CheckCircle2 className on "All Systems Operational" banner: "w-10 h10" (missing
   dash before 10). The icon will not render at the correct size — h-10 is missing, so the
   element gets no explicit height from Tailwind.

3. Header row has no flex-wrap: on mobile, "Last checked: HH:MM:SS AM · v3.1.0 · uptime Xh Ym"
   can overflow or push against the Refresh button. No wrapping or text truncation is applied.

4. Brand leak: COMPONENT_LABELS includes 'picoclaw' mapped to 'Weebo Engine'. This is an
   internal mapping artifact — the visible label "Weebo Engine" is fine, but the key 'picoclaw'
   in the component map is only safe as long as the API returns that key. If the API key changes,
   the row silently disappears (filtered out). No fallback.

5. "All systems operational" check: uses entries (filtered to known labels). If the API adds
   new component keys not in COMPONENT_LABELS, they are silently excluded from the allOk
   calculation. A failing unknown component would not degrade the banner.

6. Contact support line uses a plain <span> instead of a mailto: link, making it harder for
   users to act on support contact (especially on mobile where tapping opens nothing).

7. No Redis component in COMPONENT_LABELS despite Redis being a critical infrastructure service.
   Health API returns redis status but it is not shown to users.
