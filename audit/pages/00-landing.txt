=== LOGIC ISSUES ===
1. "Live Activity" section shows hardcoded fake data with real-looking timestamps ("2s ago", "5s ago") but the timestamps never update — they freeze on mount. Misleading to users who expect live data.
2. "Live updates from the network" indicator is always green/pulsing regardless of actual network activity. False signal.
3. Stats (2.4M+ Messages, 99.99% Uptime) are hardcoded strings — not pulled from any API.
4. ConstellationSection search filters the hardcoded `companies` array, not the real explore directory. If a user types a name, they'll only match the 8 demo names (alex, sarah, marcus, etc.) including "Riley Reid" and "Taylor Swift" — famous names used as placeholders that could appear confusing or unprofessional.
5. SecuritySection "Review Security" button navigates to /docs — this route is not defined in the application and will 404.
6. Footer "Docs" and "Status" links also go to /docs and /status — likely 404 routes.
7. PromptTemplatesSection uses framer-motion (motion components) while other sections use manual IntersectionObserver — inconsistent animation approach across the landing page.
8. ConstellationSection: Math.random() is called inside useMemo for dot positions — this is acceptable since useMemo runs once, but the values will differ between SSR and hydration if SSR is ever added.
9. "SOC 2 Compliant" and "GDPR Ready" badges in ContactSection appear to be marketing claims not backed by visible certification evidence.
10. The /login?redirect=design and /login?redirect=automations query params are accepted by LoginPage but there's no redirect logic in LoginPage to actually redirect after login based on those params — the redirect param is silently ignored.
