=== LOGIC ISSUES ===
1. ASSIGNED AGENT IS DECORATIVE: The assigned agent is stored in state and localStorage but never sent to the generate API call. `handleGenerate` calls `imageService.generate(prompt, selectedModel, width, height)` with no agent context. The "Assign Agent" UI is misleading — it implies the agent does the generation.

2. POLLINATIONS STATUS CHECK IS WRONG: The model status endpoint pings `image.pollinations.ai` (which is BLOCKED from Hostinger — returns 530). This will always report 'pollinations' model as 'down' even though auto-select falls back to HuggingFace. The model status for 'pollinations' will consistently show red dot, confusing users.

3. EDIT MODE: Reference image uploaded as base64 data URL and sent as `reference_url` to the backend. The backend (POST /api/images/edit) does NOT actually use the reference image URL in the generation call — it only prepends "Based on this reference image concept" to the prompt text. There is no true img2img. Users are misled into thinking the reference image is used visually.

4. NO PROMPT SUBMISSION ON ENTER: Textarea does not submit on Ctrl+Enter. For a generation tool, this is a common UX expectation.

5. DOWNLOAD LINK IS NOT A DIRECT DOWNLOAD: The download button opens `image_url` in a new tab (`target="_blank"`). This works for HuggingFace cached images served from the app's own server, but for Pollinations CDN URLs, the image may not have a download header. No `download` attribute is set on the anchor tag in the lightbox.

6. GALLERY IMAGE LIMIT UI: When imageCount >= maxImages, the generate button is disabled and a red message shows. However, no explicit message tells the user to delete images to make room — only "Check your gallery below" in the success toast. The info box at the bottom explains this, but users may not scroll there.

7. MODEL AUTO-SELECT LOGIC MISMATCH: Auto-select in the UI shows 'auto' as selection, but the server resolves it based on credits. If the user selects 'auto' in the UI with zero credits, the server picks 'pollinations' (which is blocked) then falls back to HuggingFace. This chain works but status dots don't reflect actual provider used.

=== SERVER ROUTES USED ===

POST /api/images/edit                — generate image with edit prompt (NOT true img2img)

GET  /api/agent/config               — load preferred_image_model

GET  /api/pico/agents                — load fleet agents for picker
