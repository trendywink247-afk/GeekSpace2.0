=== LOGIC ISSUES ===
- EventSource does not send authentication headers (browsers don't support this natively).
  The /api/health/stream endpoint may require auth. If the auth is cookie-based or if the
  stream endpoint is publicly accessible, this works fine. If it requires a Bearer token,
  the SSE connection will fail silently (401) and fall back to REST.
  Need to verify server-side auth on the health stream route.
- When SSE fallback occurs (REST polling every 10s), `connected` is set to `false`.
  The UI shows "Disconnected" with an error message even though data is being polled
  correctly via REST. This is technically accurate but may alarm users unnecessarily.
  Consider showing "Polling mode" or a separate indicator.
- Retry button: 24px height (h-6) is too small for mobile touch targets.
- `retriesRef` is not reset when handleRetry is called INSIDE the onerror handler path
  (when MAX_RETRIES is hit and REST fallback starts). If the user manually hits Retry,
  `retriesRef.current = 0` is reset correctly, but if auto-retry somehow triggers again,
  the counter could reach MAX_RETRIES quickly.
- `reconnectTimerRef` is cleared on manual retry but the REST interval (`restIntervalRef`)
  is also cleared on retry — this is correct, but if the user hits Retry while REST
  polling is active, the interval is cleared and SSE reconnection starts, which is the
  right behavior.
- The component always shows 'picoclaw' component data under label 'Weebo Engine' —
  brand-safe alias is correctly applied.
- No auto-reconnect after successful REST fallback when SSE eventually becomes available
  again (stays on polling forever once MAX_RETRIES is hit).
