=== LOGIC ISSUES ===
- Projects, milestones, and skills changes are all accumulated in local state and saved
  together when "Save" is clicked. If the user edits a project, edits a milestone, then
  navigates away without saving, all changes are lost. No unsaved changes warning
  (unlike SettingsPage which has a beforeunload guard).
- Drag-to-reorder uses HTML5 drag events which do not work on mobile touch screens.
  The GripVertical icon suggests drag is the intended mechanism, but touch users have
  no way to reorder projects.
- `metaDescription` is loaded from the portfolio data but uses a cast:
  `(data as unknown as Record<string, unknown>).meta_description` — this indicates
  the Portfolio type definition doesn't include meta_description field. It's accessed
  via unsafe cast, meaning TypeScript won't warn if this field is renamed/removed server-side.
- The `handleSave` function passes `metaDescription` as a field to `portfolioService.update()`
  but the update function signature likely takes the Portfolio type which may not include
  meta_description. This could silently drop the metaDescription field on save.
  Same applies to the Portfolio type not including `view_count` (accessed via cast).
- Magic Generate preview: `generateTarget` is set when generate starts, and `generatedPreview`
  is set on success. But if two fields generate simultaneously (race condition), `generateTarget`
  would be overwritten. The UI likely prevents this via `generatingField` state, but only
  one field can generate at a time.
- `loadingSuggestions` has no error state — if suggestions fail to load, the section
  just shows nothing (silent failure). Users won't know suggestions are unavailable.
- The `handleExportCsv` function creates a Blob from response.data but casts it as
  `BlobPart` — this works if the server returns text/csv content but is type-unsafe.
