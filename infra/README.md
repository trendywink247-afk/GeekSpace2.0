# Agentin Infrastructure

> Component-level documentation for all infrastructure services in the Agentin platform.

---

## Overview

The Agentin platform runs on a single VPS with 15+ services orchestrated via Docker Compose, plus host-managed services (Ollama, Caddy). All services communicate over two Docker networks.

For deployment procedures and operational checklists, see [`docs/DEVOPS.md`](../docs/DEVOPS.md).

---

## Components

### Caddy (Reverse Proxy)

| Property | Value |
|----------|-------|
| Location | Host-level binary (not Docker) |
| Config source | `caddy/Caddyfile` |
| Active config | `/etc/caddy/Caddyfile` |
| Port | 443 (HTTPS), 80 (HTTP redirect) |
| TLS | Auto-HTTPS via Let's Encrypt |

**Responsibilities:**
- TLS termination for all domains
- Reverse proxy to Docker containers
- Static file serving for React SPA (`/srv/`)
- Security headers (CSP, HSTS, X-Frame-Options)
- SSE stream handling (`flush_interval -1`)
- Admin path blocking on public domains

**Domain routing:**

| Domain | Target | Notes |
|--------|--------|-------|
| `ai.agentin.chat` | geekspace:3001 | Production (SPA + API) |
| `api.agentin.chat` | geekspace:3001 | API only (blocks /admin) |
| `staging.agentin.chat` | staging:3001 | Staging environment |
| `ai.geekspace.space` | staging:3001 | Legacy test domain |
| `status.agentin.chat` | uptime-kuma:3001 | Monitoring dashboard |

### PicoClaw (AI Triage Sidecar)

| Property | Value |
|----------|-------|
| Source | `picoclaw/` |
| Runtime | Node.js (Express) |
| Model | qwen2.5-coder:1.5b (via Ollama) |
| Port | 8080 |
| Memory | 64MB |
| Health | `GET /health` |

**Purpose:** Fast AI triage for simple/code-micro intents. Routes through Ollama for inference. Has a circuit breaker: 1 failure triggers a 5-minute cooldown, during which the main app skips PicoClaw and routes directly to cloud providers.

### SearXNG (Metasearch)

| Property | Value |
|----------|-------|
| Image | `searxng/searxng:2026.3.12-3d3a78f3a` |
| Config | `searxng/settings.yml` (mounted read-only) |
| Port | 8080 (internal) |
| Memory | 256MB |

**Purpose:** Free, self-hosted metasearch aggregating results from multiple search engines. Replaces paid Tavily as the primary web search provider. Tavily remains as a fallback for premium users.

### Meilisearch (Instant Search)

| Property | Value |
|----------|-------|
| Image | `getmeili/meilisearch:v1.12` |
| Port | 7700 (internal) |
| Memory | 128MB |
| Auth | `MEILI_MASTER_KEY` env var |

**Purpose:** Typo-tolerant instant search across notes, reminders, habits, and memories. Indexes are maintained by the backend's `search-index.ts` service.

### Qdrant (Vector Database)

| Property | Value |
|----------|-------|
| Image | `qdrant/qdrant:v1.13.2` |
| Port | 6333 (HTTP), 6334 (gRPC) |
| Memory | 256MB |
| Volume | `qdrant-data` |

**Purpose:** Vector similarity search for semantic memory. Stores embedding vectors generated by Ollama's `nomic-embed-text` model. Used by `memory.ts` and `search-vector.ts` services for context-aware agent responses.

### Browser Agent (Headless Browser)

| Property | Value |
|----------|-------|
| Source | `browser-agent/` |
| Port | 3010 (internal) |
| Memory | 1.5GB |
| Concurrency | 2 simultaneous sessions |
| Auth | `BROWSER_SECRET` env var |

**Purpose:** Headless Chromium browser for screenshots, web scraping, and page rendering. Used by the agent's screenshot and web research tools.

### Redis

| Property | Value |
|----------|-------|
| Image | `redis:7-alpine` |
| Port | 6379 |
| Memory | 256MB (LRU eviction) |
| Persistence | AOF (appendonly) |
| Auth | `REDIS_PASSWORD` required |

**Purpose:** Multi-purpose cache and data store:
- Rate limiting buckets (express-rate-limit)
- LLM response cache (L2, 5-min TTL)
- Job queue persistence
- Session state
- Together AI daily budget tracking

### Uptime Kuma (Monitoring)

| Property | Value |
|----------|-------|
| Image | `louislam/uptime-kuma:1` |
| Port | 3100 (mapped from internal 3001) |
| Memory | 128MB |
| URL | `status.agentin.chat` |

**Purpose:** Service uptime monitoring with alerting. Monitors production, staging, and external service endpoints.

### n8n (Workflow Automation)

| Property | Value |
|----------|-------|
| Image | `n8nio/n8n:1.78.1` |
| Port | 5678 (localhost only) |
| Memory | 512MB |
| Profile | `n8n` (optional, not started by default) |

**Purpose:** Visual workflow automation platform. Used for complex multi-step automations that go beyond the built-in automation engine. Bound to localhost for security.

**Start:** `docker compose --profile n8n up -d n8n`

### Ollama (Local LLM)

| Property | Value |
|----------|-------|
| Manager | systemd / Hostinger (host-level) |
| Port | 11434 |
| Network | `geekspace-shared` (external) |
| Models | hermes3:8b, qwen2.5-coder:1.5b, nomic-embed-text |

**Purpose:** Local LLM engine providing private inference. Primary model is `hermes3:8b` for general chat, `qwen2.5-coder:1.5b` for PicoClaw triage, and `nomic-embed-text` for generating 768-dim embeddings for vector search.

## Docker Build

The application uses a multi-stage Dockerfile:

| Stage | Base | Purpose |
|-------|------|---------|
| **builder** | node:20-alpine | Install deps, compile TypeScript, build Vite frontend |
| **production** | node:20-slim | Copy compiled output, production deps only, run as non-root |

**Runtime dependencies installed in production image:**
- `ca-certificates`, `curl` -- HTTPS + healthchecks
- `git`, `gh` -- Git operations + GitHub CLI (for dev-runner)
- `python3`, `python3-venv` -- edge-tts (TTS engine)
- `ffmpeg` -- Audio/video processing

**Process manager:** PM2 (`pm2-runtime`) for cluster mode with automatic restart.

## Centralized Logging (Loki + Grafana + Promtail)

A separate Docker Compose stack for centralized log aggregation and visualization. Promtail tails container logs from all services on the host, parses Pino JSON output, and ships them to Loki. Grafana provides a dashboard UI for querying and exploring logs.

| Component | Image | Purpose |
|-----------|-------|---------|
| **Loki** | `grafana/loki:3.0.0` | Log storage and query engine |
| **Grafana** | `grafana/grafana:11.0.0` | Visualization and dashboards |
| **Promtail** | `grafana/promtail:3.0.0` | Log collector (tails Docker container logs) |

**Config files:**
- `infra/loki-config.yaml` -- Loki storage, retention (7 days), and compactor settings
- `infra/promtail.yml` -- Scrape config for Docker container logs with Pino JSON parsing

### Usage

```bash
# Start the logging stack (uses the shared geekspace-net network)
docker compose -f docker-compose.logging.yml up -d

# Open Grafana at http://localhost:3200
# Default credentials: admin / (GRAFANA_PASSWORD env var, defaults to "admin")

# Add Loki as a data source in Grafana:
#   URL: http://loki:3100
```

### Notes

- Port 3100 is already mapped to Uptime Kuma on the host, so Loki is only accessible within the `geekspace-net` Docker network. Grafana connects to it internally as `http://loki:3100`.
- Promtail requires read access to `/var/lib/docker/containers` and `/var/run/docker.sock` on the host.
- Log retention is set to 7 days. Adjust `retention_period` in `infra/loki-config.yaml` to change.
- Set `GRAFANA_PASSWORD` in your environment or `.env` file before starting the stack.
