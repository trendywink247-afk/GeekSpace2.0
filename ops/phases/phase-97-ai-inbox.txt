## Step 2 — DB schema
```sql
CREATE TABLE IF NOT EXISTS inbox_messages (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  source TEXT NOT NULL,       -- 'telegram' | 'whatsapp' | 'system' | 'agent'
  sender TEXT,                -- display name or phone
  content TEXT NOT NULL,
  summary TEXT,               -- AI-generated 1-sentence summary
  priority TEXT DEFAULT 'normal', -- 'urgent' | 'high' | 'normal' | 'low'
  read INTEGER DEFAULT 0,
  archived INTEGER DEFAULT 0,
  suggested_reply TEXT,       -- AI-generated reply suggestion
  related_reminder_id INTEGER REFERENCES reminders(id),
  received_at INTEGER NOT NULL DEFAULT (unixepoch('now') * 1000)
);
CREATE INDEX IF NOT EXISTS idx_inbox_user ON inbox_messages(user_id, read, received_at DESC);
```

## Step 3 — Inbox service (server/src/services/inbox.ts)
- `addInboxMessage(userId, source, sender, content)` — insert + trigger AI triage
- `triageMessage(messageId)` — call LLM to:
  1. Generate 1-sentence summary (max 100 chars)
  2. Classify priority (urgent if contains deadline/ASAP/help, high if question, normal otherwise)
  3. Suggest a short reply (1-2 sentences) if it's a question or needs response
  4. Detect if related to an existing reminder (keyword match)
  Update the inbox_messages row with these fields.
- `getInbox(userId, { unreadOnly, limit })` — return messages newest-first
- `markRead(userId, messageId)` — set read=1
- `archiveMessage(userId, messageId)` — set archived=1
- `getUnreadCount(userId)` — fast count for badge

## Step 4 — Wire message-router.ts to inbox
When a Telegram or WhatsApp message arrives and is handled by the message router,
also call `addInboxMessage(userId, 'telegram'/'whatsapp', sender, content)`.
Do NOT change existing routing logic — just add inbox side-effect.

## Step 5 — Inbox routes (server/src/routes/inbox.ts)
```
GET    /api/inbox                  — list messages { unreadOnly?, limit?, offset? }
GET    /api/inbox/count            — { unread: N }
PATCH  /api/inbox/:id/read         — mark read
PATCH  /api/inbox/:id/archive      — archive
DELETE /api/inbox/:id              — hard delete
POST   /api/inbox/:id/reply        — send suggested reply via original channel
```
